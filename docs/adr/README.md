# Architecture Decision Records

Architecture Decision Records document significant technical decisions made during the BRONNIE project.

Each ADR should describe:

* Context
* Decision
* Alternatives considered
* Rationale
* Consequences
* Status

## Naming

ADRs use sequential numbering.

Examples:

`ADR-001-monorepo.md`

`ADR-002-aws-cloud-platform.md`

`ADR-003-backend-framework.md`

## Status

An ADR may be:

* Proposed
* Accepted
* Superseded
* Rejected

Architecture decisions should be documented when they are made rather than reconstructed after implementation.
